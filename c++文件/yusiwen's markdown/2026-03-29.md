## 1. 代码功能与建模逻辑

这道题的精妙之处在于将单词转化为图中的**边**，而不是点：
* **点（Node）**：26 个小写字母。
* **边（Edge）**：每个单词。起点是首字母，终点是末字母。
* **目标**：寻找一条经过所有边且仅经过一次的路径。



### 核心步骤解析：
1.  **构图与度数统计**：
    使用 `in[i]` 和 `out[i]` 统计每个字母作为首字母和尾字母出现的次数。
2.  **寻找起点**：
    * **欧拉路径**：必须存在一个点 $out - in = 1$（起点）和一个点 $in - out = 1$（终点），其余点 $in = out$。
    * **欧拉回路**：所有点 $in = out$。此时起点应选字母表中最小的那个（为了满足字典序）。
3.  **排序**：
    为了保证字典序最小，对每个顶点的出边按照字符串升序排列。在 DFS 时，优先遍历字典序小的单词。
4.  **Hierholzer 算法**：
    通过 DFS 遍历边，并在回溯时将边加入结果序列。

## 2. 重点语法与细节说明

### 当前弧优化
```cpp
while(idx[x] < g[x].size()){
    string v = g[x][idx[x]].first;
    ll u = g[x][idx[x]].second;
    idx[x]++; // 关键：记录当前处理到第几条边
    dfs(u);
    ans.push_front(v);
}
```
* `idx[x]` 确保了每条边只被访问一次。在竞赛中，如果直接删除 vector 元素或频繁扫描已访问标记，复杂度会退化。这种“指针移动”的方式是处理欧拉回路的标准姿势。

### 逆序存储
* **为什么用 `push_front`？** 欧拉路径的特性是：最后完成递归的点一定是路径的终点。因此回溯时最先拿到的单词是词链的末尾，使用 `deque::push_front` 或 `vector` 存储后 `reverse` 才能得到正确顺序。

## 3. 逻辑漏洞与竞赛避坑指南

作为你的教练，我发现代码中有几个地方如果不修正，在测评机上会吃 **WA (Wrong Answer)**：

### ① 致命伤：连通性判定
代码只检查了度数，但**度数合法不代表图是连通的**。
* **场景**：如果输入中有两个独立的单词环（例如 `ab, ba` 和 `cd, dc`），度数检查会通过，但无法形成一条完整的词链。
* **修正建议**：在执行完 `dfs(start)` 后，必须判断结果集 `ans.size()` 是否等于单词总数 `n`。如果不相等，说明图不连通，输出 `***`。

### ② 排序循环范围错误
```cpp
for(int i=1;i<=n;i++){ // 这里的 i 应该是字母编号
    sort(g[i].begin(),g[i].end());
}
```
* **错误分析**：题目中字母只有 26 个，但 $n$ 可以到 1000。如果 $n > 26$，由于 `g` 的大小只有 35，这里会发生**越界访问**；如果 $n < 26$，则部分字母的出边没有被排序。
* **修正**：应改为 `for(int i=1; i<=26; i++)`。

### ③ 最小起点的选择
```cpp
if(g[i].size()>=1&&i<id2) id2=i;
```
* 这个逻辑用于寻找欧拉回路的起点（即所有点 $in=out$ 时）。它选取了编号最小的且有出边的字母，这是正确的，能保证字典序最小。
